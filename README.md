What's here

Most of this is one system wearing different hats: a personal agentic platform that has run my home infrastructure 24/7 for the past year — AI agents doing real operational work under real governance. The questions enterprises are starting to ask about agentic AI — what can an agent touch? who approved that? what did it cost? what does it remember? — are questions this platform answers in running code.

atlas-framework — the coordination layer. One schema-validated record of what exists, what work is in flight, and what each actor — human or agent — is permitted to do. Rules as data, propose-confirm writes, drift detection between declared state and reality, every human-facing view generated rather than maintained.
operator-kernel — the constrained alternative to "give the agent a shell." Observes before it plans, plans only from pre-authored runbooks, executes only against an explicit approval token, and leaves a proof artifact for every run.
rubric-judge — a two-stage watch pipeline: deterministic gates in code, an LLM judge scoring what survives against a prose policy rubric, an append-only audit trail, and a feedback loop that turns one-sentence operator corrections into permanent behavior.
Mimecast-API-Action-Pack and MimecastAPI2.0 — field tooling. What pre-sales engineering looks like when you automate it: 257 endpoints, starter scripts, and a prompt pack that lets an AI assistant scaffold a working integration workspace from one paste.
remote-mcp-server — lessons learned standing up remote MCP servers: connector auth, session memory, keeping keys server-side.
Hardware — CNC-Air-Blaster, Oven-Temp-Monitor — same instinct, different substrate. If I depend on it, I want to understand it down to the metal.
